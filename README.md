# QR 傳檔

用螢幕上的 QR Code 把檔案從一台不能連網的電腦傳到手機。

- `sender-ie11.html`：傳送端。單一檔案、無外部依賴、純 ES5，可在 IE11 開啟。把檔案切片成標準 QR Code（Version 1～40、容錯 L）輪播。
- `index.html`：接收端。手機瀏覽器開啟，鏡頭對著傳送端畫面，自動依頁碼重組並下載。解碼全在手機本機完成，不上傳任何資料。

## 用法

1. 把 `sender-ie11.html` 存到離線電腦，用瀏覽器開啟，選檔案，按「自動輪播」。
2. 手機開接收頁，按「開始掃描」，對著畫面直到進度條跑滿。
3. 按「下載檔案」。噴泉碼會自動驗證 CRC32；帶頁碼標籤請核對兩邊顯示的 CRC32 相同。

## 格式

- **噴泉碼（預設，協定第 2 版）**：每張 = 17 位元組檔頭（`QF`、版本、資料流 CRC32、長度、塊大小 K、種子）+ K 位元組資料。
  - 資料流 = 旗標 + 檔名長度 + 檔名 + [原始檔 SHA-256] + [原始長度] + 內容（可為 gzip），切成 N 塊。
  - 種子小於 N 的張是原文；其餘是補償張：所有塊依「塊號 mod G」分成 G = ceil(N/1024) 組，每張補償張是某一組內隨機挑出的塊 XOR 在一起。
  - 接收端逐組做 GF(2) 高斯消去，運算量與記憶體都和檔案大小成正比；收齊後驗證 CRC32 與 SHA-256，必要時解壓。
  - 這不是 RaptorQ（RFC 6330），是比較簡單的分組隨機線性碼；模擬中比理論最少多播 1～8%。
  - 文字版是 `QF1:` + 整張的 Base64。接收端同時支援第 1 版（不分組、無 SHA-256）。
- **純文字直出**：把一段文字／設定檔／金鑰直接轉成 QR，手機掃到直接讀，不還原成檔案。

## 加密（選用）

在傳送端的「加密密碼」欄輸入密碼即加密；手機收齊後會要求輸入相同密碼才能解開。

- 金鑰 = PBKDF2-HMAC-SHA256（密碼 UTF-8、16 位元組隨機 salt、150,000 次迭代、32 位元組）。
- 串流加密 = ChaCha20（RFC 8439，12 位元組隨機 nonce，counter 從 0），每次傳輸 salt／nonce 都重新亂數產生。
- 被加密的是整個內層資料流（含**檔名**），所以連檔名都不外洩。密碼錯誤會因內層的明文 SHA-256 比對失敗而被拒絕（並非形式上的 AEAD；完整性靠該 SHA-256，而非 Poly1305 之類的 MAC）。
- 加密容器：`0xE1 | 版本 | iters(4) | salt(16) | nonce(12) | ChaCha20 密文`；外層再照常走噴泉碼，CRC32 驗證傳輸、SHA-256 驗證解密。
- **密碼只在執行時於兩端輸入，不會寫進程式碼、也不在此 repo 裡。** 程式碼公開不影響安全性——安全性取決於密碼。
- 傳送端在 IE11 上用純 ES5 實作全部加密（WebCrypto 不可用）；接收端有 WebCrypto 時用它導金鑰，沒有則用純 JS。兩種實作均以 Node 的 `crypto` 與 RFC 8439 測試向量逐位元組驗證過。

## 格式（續）

- **帶頁碼標籤**（接收端仍支援，傳送端選單已移除）：`頁/總頁|檔名|Base64 片段`。

`sender-ie11-prev.html` 是上一版傳送端，新接收頁仍可接收。
